# Overview

ForgeMind is a Universal Software Intelligence Platform that transforms software systems into a living, continuously evolving knowledge graph.

Unlike traditional developer tools that analyse source code, generate code, or perform static analysis, ForgeMind understands software as an interconnected system consisting of code, architecture, infrastructure, databases, APIs, deployments, runtime behaviour, and engineering knowledge.

ForgeMind provides engineers with a complete understanding of how software works, how components interact, what changes impact the system, and why specific behaviours occur.

It continuously analyses repositories, detects live changes, updates its understanding incrementally, and provides explainable insights powered by graph-based reasoning rather than simple text generation.

ForgeMind is designed to become the intelligence layer between developers and software systems.

# Universal Intermediate Representation (UIR)

> **The Universal Language of ForgeMind**

---

# Overview

The Universal Intermediate Representation (UIR) is the semantic foundation of ForgeMind.

Every repository imported into ForgeMind is converted into a common language-independent representation before any intelligence, reasoning or analysis takes place.

Instead of understanding programming languages, ForgeMind understands software concepts.

This enables every component of ForgeMind to operate consistently regardless of the technologies used inside the repository.

---

# Why UIR Exists

Every programming language expresses similar software concepts using different syntax.

For example,

Java

```java
public class UserService {

    public User login(){}

}
```

Python

```python
class UserService:

    def login(self):
        pass
```

Go

```go
type UserService struct {}

func (u UserService) Login() {}
```

Rust

```rust
impl UserService {

    fn login() {}

}
```

Although the syntax differs, every example represents the same software concept.

Without UIR, ForgeMind would require a completely different intelligence engine for every programming language.

With UIR, ForgeMind only needs one intelligence engine.

---

# Core Philosophy

> **Different syntax. Same software.**

The purpose of UIR is not to preserve syntax.

The purpose is to preserve meaning.

# Glossary

> **ForgeMind Terminology and Definitions**

---

# Overview

This document defines the terminology used throughout the ForgeMind documentation.

It provides a common understanding of the concepts, components and technologies that make up the platform.

---

# AI Context Export

A feature that generates structured project intelligence from the Software Digital Twin.

The exported package can be shared with developers or AI systems to provide immediate understanding of a software project without requiring repeated repository analysis.

---

# Analysis

The process of transforming a software repository into structured software knowledge.

Analysis includes:

- Language detection
- Parsing
- Semantic analysis
- Relationship extraction
- Digital Twin generation

---

# API Gateway

The entry point for all external requests.

Responsibilities include:

- Authentication
- Authorization
- Request routing
- Rate limiting
- Request validation

---

# Architecture Discovery

The process of identifying software architecture automatically from source code and project metadata.

Examples include:

- Layered Architecture
- Microservices
- Event-Driven Architecture
- Modular Monolith

---

# Blast Radius

The estimated scope of a software change.

Blast radius identifies every component that may be affected by a modification.

Examples include:

- Services
- APIs
- Databases
- Infrastructure
- Runtime dependencies

---

# Change Impact Analysis

The process of predicting how a change affects the software system before deployment.

The analysis is based on relationships stored in the Software Knowledge Graph and Software Digital Twin.

---

# Digital Twin

A continuously evolving virtual representation of a software system.

The Digital Twin combines:

- Source code
- Architecture
- Infrastructure
- Runtime behaviour
- Deployments
- Dependencies

It acts as the primary intelligence model within ForgeMind.

---

# Graph Node

A software component stored inside the Software Knowledge Graph.

Examples include:

- Service
- API
- Function
- Database
- Deployment
- Container

---

# Graph Relationship

A connection between two graph nodes.

Examples include:

- DEPENDS_ON
- CALLS
- READS
- WRITES
- PUBLISHES
- SUBSCRIBES

---

# Incremental Analysis

A processing strategy where only modified software components are re-analysed after repository changes.

This reduces processing time and avoids rebuilding the complete software model.

---

# Knowledge Graph

A graph-based representation of software components and their relationships.

The Knowledge Graph provides the structural foundation for the Software Digital Twin.

---

# Language Detection

The process of identifying programming languages, frameworks and build systems used within a repository.

---

# Parser

A component that converts source code into a structured representation for further analysis.

Parsers are language-specific.

---

# Polyglot Persistence

A storage strategy where multiple database technologies are used based on the type of data being stored.

ForgeMind uses:

- PostgreSQL
- Neo4j
- Redis
- Object Storage

---

# Repository Analysis

The complete process of understanding a software repository.

Repository analysis includes:

- Repository cloning
- Parsing
- Semantic analysis
- Graph generation
- Digital Twin generation

---

# Repository Watcher

A service that continuously monitors repositories for changes.

Examples include:

- File updates
- Commits
- Pull requests
- Branch merges

---

# Runtime Intelligence

The capability of correlating runtime telemetry with software architecture.

Runtime Intelligence connects:

- Logs
- Metrics
- Traces
- Deployments

to the Software Digital Twin.

---

# Semantic Analysis

The process of converting language-specific syntax into language-independent software concepts.

Instead of identifying syntax, semantic analysis identifies software meaning.

---

# Software Intelligence

The ability to understand software systems by analysing their structure, relationships and behaviour.

ForgeMind provides software intelligence through the Software Digital Twin.

---

# Software Knowledge Graph

A graph database representation of software entities and their relationships.

It enables dependency analysis, graph traversal and software reasoning.

---

# Software Digital Twin

The central intelligence model of ForgeMind.

The Software Digital Twin continuously represents the current state of a software system by combining repository information, architecture, runtime behaviour and infrastructure into a unified model.

---

# Universal Intermediate Representation (UIR)

A language-independent representation of software concepts.

All supported programming languages are transformed into the UIR before intelligence processing begins.

This enables ForgeMind to analyse software consistently across multiple languages.

---

# Runtime Correlation

The process of connecting runtime events with the software components responsible for them.

Examples include linking:

- Errors
- Deployments
- Services
- APIs
- Infrastructure

---

# Repository Synchronisation

The process of keeping the Software Digital Twin aligned with the latest state of the repository.

Synchronisation occurs whenever the repository changes.

---

# Service

A logical software component that provides a specific business capability.

Examples include:

- Authentication Service
- Payment Service
- Order Service

---

# Workspace

A logical environment where users manage projects, repositories and analysis results.

A workspace may contain multiple repositories and multiple team members.

---

# Summary

This glossary provides a shared vocabulary for ForgeMind.

By defining the platform's key concepts in one place, it ensures that developers, contributors and users interpret the documentation consistently and can quickly understand the terminology used throughout the project.

# Workflow Orchestrator

> **Coordinating Long-Running Platform Workflows**

---

# Overview

The Workflow Orchestrator is responsible for coordinating long-running workflows across ForgeMind.

It acts as the central coordinator for repository analysis, software intelligence generation and platform automation.

Rather than allowing services to call each other directly, every major workflow is coordinated through the Workflow Orchestrator.

This keeps services loosely coupled while improving reliability, scalability and observability.

---

# Purpose

ForgeMind contains multiple long-running operations.

Examples include:

- Repository Import
- Repository Synchronisation
- Repository Analysis
- Software Digital Twin Updates
- AI Context Generation
- Runtime Correlation
- Report Generation

These operations involve multiple services and cannot be completed within a single request.

The Workflow Orchestrator coordinates these operations.

---

# Responsibilities

The Workflow Orchestrator is responsible for:

- Workflow orchestration
- Job scheduling
- Job tracking
- Retry handling
- Timeout management
- Failure recovery
- Progress reporting
- Event coordination

---

# Why It Exists

Without an orchestrator:

```text
Repository Service

↓

Parser Service

↓

Semantic Service

↓

UIR Service

↓

Knowledge Graph

↓

Digital Twin
```

Every service becomes aware of the next service.

This creates tight coupling.

---

With an orchestrator:

```text
Repository Imported

↓

Workflow Orchestrator

↓

Parser

↓

Workflow Orchestrator

↓

Semantic Analysis

↓

Workflow Orchestrator

↓

UIR

↓

Workflow Orchestrator

↓

Knowledge Graph

↓

Workflow Orchestrator

↓

Digital Twin

↓

Workflow Completed
```

Each service performs only its own responsibility.

---

# Software Reasoning Engine

> **Explainable Engineering Reasoning for Complex Software Systems**

---

# Overview

The Software Reasoning Engine is the decision-making layer of ForgeMind.

Its purpose is to answer engineering questions by analysing the Software Digital Twin, Software Knowledge Graph, Runtime Intelligence and historical repository information.

Unlike traditional AI assistants, the Software Reasoning Engine does not generate answers by predicting text.

Instead, it performs structured reasoning based on software relationships, engineering rules and observable evidence.

Every conclusion is supported by traceable data.

---

# Purpose

Modern software systems contain thousands of interconnected components.

Understanding how these components influence one another is difficult.

The Software Reasoning Engine helps engineers answer questions such as:

- Why is this service failing?
- What caused this deployment issue?
- Which services depend on this API?
- Why is this component considered high risk?
- What changed before the incident?
- Which repository introduced this dependency?
- What is the safest deployment order?

Every answer includes supporting evidence.

---

# Objectives

The Software Reasoning Engine is designed to:

- Explain software behaviour.
- Explain architecture.
- Explain dependencies.
- Explain runtime behaviour.
- Explain engineering decisions.
- Explain impact analysis.
- Recommend engineering actions.

---

# Inputs

The engine combines information from multiple platform components.

Sources include:

- Software Digital Twin
- Software Knowledge Graph
- Runtime Intelligence
- Repository Analysis
- Dependency Analysis
- Deployment History
- Repository History
- Engineering Metadata

---

# Outputs

The engine produces:

- Engineering explanations
- Dependency reasoning
- Root cause analysis
- Risk explanations
- Change explanations
- Architecture insights
- Deployment recommendations
- Engineering evidence

# Policy Engine

Rather than manually reviewing software systems, engineering teams define policies once and ForgeMind continuously verifies them.

The Policy Engine automates policy evaluation and continuously validates software systems against engineering rules.

- Reduce operational risk

# Universal Intermediate Representation (UIR) Specification

> **Language-Independent Software Model for ForgeMind**

---

# Overview

The Universal Intermediate Representation (UIR) is the canonical software model used throughout ForgeMind.

Every supported programming language is transformed into the UIR before further processing.

The UIR enables ForgeMind to understand software independently of programming language, framework or implementation details.

It serves as the common language between repository parsing, semantic analysis, the Software Knowledge Graph, the Software Digital Twin and the Software Reasoning Engine.

---

# Purpose

Different programming languages describe software differently.

Examples

Java

```java
class PaymentService {}
```

TypeScript

```typescript
class PaymentService {}
```

Python

```python
class PaymentService:
```

Although the syntax differs, the software concept is identical.

The UIR represents all of these as:

```text
Component

Type: Class

Name: PaymentService
```

# Design Rules

The UIR should:

- Represent meaning, not syntax.
- Be deterministic.
- Preserve source traceability.
- Support incremental updates.
- Remain language independent.
- Be easy to serialize.
- Be easy to validate.

# ForgeMind

> **The Universal Software Intelligence Platform**

ForgeMind is an enterprise-grade Software Intelligence Platform that transforms any software repository into a structured knowledge graph, enabling developers to understand complex software systems instead of manually analysing thousands of files.

Unlike traditional code analysis tools that only inspect source code or AI tools that repeatedly scan repositories, ForgeMind creates a **Universal Intermediate Representation (UIR)** of the entire project. This representation captures software concepts rather than language-specific syntax, allowing ForgeMind to understand repositories written in different programming languages using the same reasoning engine.

The platform analyses not only source code but also project architecture, APIs, databases, infrastructure, CI/CD pipelines and runtime relationships to provide a complete understanding of the software system.

---

# Why ForgeMind?

Modern software development has become increasingly complex.

Large projects often contain:

- Multiple programming languages
- Hundreds of services
- Thousands of APIs
- Distributed infrastructure
- CI/CD pipelines
- Databases
- Event-driven communication
- Cloud-native deployments

Understanding these systems requires developers to switch between many disconnected tools and manually connect information.

ForgeMind brings all of this knowledge together into one intelligent platform.
